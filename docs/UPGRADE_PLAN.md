# Upgrade plan

Goal: turn the notebook prototype into a reproducible pipeline where every README number is measured by one command
(`jobinsights report`) on the full dataset, with an honest evaluation of the extraction methods.

## What the audit of the existing repo found

| # | Finding | Consequence |
|---|---------|-------------|
| 1 | The data is not in the repo and the notebooks load from hard-coded paths on another machine (`/Users/ronitgandhi/...`). | Nothing runs as cloned. Needs a download step and a path config. |
| 2 | Only the plots are committed. The CSVs the README lists under `outputs/extracted_data/` do not exist. | Results can not be reproduced or inspected. |
| 3 | Skill matching is `skill.lower() in description.lower()` (notebook 02, cell 3). That makes the skill `R` match any description containing the letter "r", `AWS` match "laws", `Excel` match "excellent", `NLP`/`SQL` match inside longer tokens. | Skill counts and the clusters built on them are inflated. The new baseline uses word-boundary regex and the evaluation set will quantify the difference against the old method. |
| 4 | Remote detection is `'remote' in desc or 'hybrid' in desc`. "Hybrid" is counted as remote, and negations ("this is not a remote role") and the dataset's own `remote_allowed` column are ignored. | Remote share is overstated. Replaced by a rule set with remote / hybrid / onsite / unknown classes. |
| 5 | Salary is only built from `min_salary`/`max_salary`, which are in mixed pay periods (hourly, monthly, yearly) and never normalised. Salary in the description text is ignored. | Salary plots mix hourly and yearly numbers. |
| 6 | `n_clusters = 10` is set and unused, `KMeans(n_clusters=15)` is hard-coded, no cluster-quality metric, no cluster names. The committed word-clouds are the only "naming". | k is arbitrary. Add silhouette / stability across seeds and automatic names. |
| 7 | The README says the dataset was prototyped on 200 rows, but the saved output of notebook 03 shows `1935` encode batches of 64 (about 123.8k rows). It is unclear which run produced the committed plots. | README claims about sample size were not verifiable. All numbers will be regenerated and the plots replaced. |
| 8 | `02_LLM_Extraction` used `flan-t5-large` on the first 700 characters and never produced a usable result ("attempted"). | Replace with a real structured-output LLM extraction and evaluate it. |
| 9 | No tests, no linting, no CI, no pinned dependencies, no LICENSE file although the README says MIT. | Add all of them. The LICENSE decision is the repo owner's (see open questions). |

## Constraints I am holding myself to

* No result goes in the README unless the command that produced it is in the repo and its output was seen.
* No large data is committed. The raw download and caches live in `data/` and `cache/` (gitignored). Small hand-label files go in `data/labels/`.
* No LLM API spend without asking first, and the run is capped and cached so it is not paid for twice.
* Where a label needs judgement, the user labels. I only pre-fill obvious cases and mark them as such.

## Steps (one or more commits each, on branch `upgrade/reproducible-pipeline`)

1. **Package + CLI.** `src/jobinsights`, `pyproject.toml`, pinned `requirements.txt`, `jobinsights download | clean | ...`.
   Download supports the Kaggle dataset `arshkon/linkedin-job-postings` through the user's own Kaggle credentials and a
   public Hugging Face subset (33,246 rows) as a no-login fallback.
2. **Scale + rules baseline.** Clean all rows. Regex extractors for skills, salary (structured columns plus text, normalised
   to annual USD) and remote/hybrid/onsite. Report coverage on the full data.
3. **LLM extraction + evaluation.** Claude structured output (tool/JSON schema), cached, on the labelled set only unless the
   user approves more. A ~150-posting evaluation set, stratified, labelled for skills / salary / remote. Report field-level
   precision / recall / F1 of old substring method vs regex baseline vs LLM, with bootstrap confidence intervals.
4. **Analysis.** Skill taxonomy (aliases to canonical skills, with families), clustering evaluation (silhouette, ARI across
   seeds, k sweep), automatic cluster names, salary regression with cross-validated MAE/R^2, a dummy baseline, and explicit
   caveats on missingness (only a minority of postings list pay, so the model describes postings that disclose pay).
5. **Dashboard.** Streamlit app: skills demand, salary by role and location, remote share. Screenshot in the README.
6. **Quality.** pytest for parsers and normalisers, ruff, GitHub Actions (ruff + pytest on a synthetic fixture so CI does not
   need the real data), README results table generated by `jobinsights report`, Limitations section.
